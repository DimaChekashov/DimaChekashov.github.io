# Почему статический подход удобен

Если блог состоит из **контента**, а не сложной бизнес-логики, то статическая сборка часто выигрывает по скорости и простоте.

## Что мы получаем

- нет базы данных
- нет backend для CRUD
- деплой одной командой

## Минимальный процесс

1. Добавляешь новый файл `README.md` с frontmatter.
2. Пушишь в репозиторий.
3. GitHub Actions публикует сайт.

> Такой подход особенно хорошо подходит для портфолио и технических заметок.
